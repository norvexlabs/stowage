# Spec keys

[README](../README.md) · [Documentation index](../README.md#documentation)

Keys of `stowage.yaml`, decoded strictly: an unknown key is an error. [examples/full](../examples/full/stowage.yaml) uses every one.

**A project without a front** ([examples/stateless](../examples/stateless/stowage.yaml)) leaves
`front` out (or empty: a `front` with anything in it is a front, linted as one). Nothing is served
over HTTP; its `l4` routes, if any, are the stack's only way in. Lint skips the front's rules and
refuses what needs one: `endpoint` (no route), an input asked in one mode only (`when`: `"tls":
the project has no front, so no TLS mode: the input would never be asked`) and a compose file
reading `${STOWAGE_TLS_MODE}`. Its installs, on Docker and the VM, run no front service and ask
nothing about one: no TLS mode is chosen or recorded (no `STOWAGE_TLS_MODE`, no route URL, no
front port; `STOWAGE_LOOPBACK_ADDRESS` is still `127.0.0.1`), no port 80 or 443 is probed, the
VM's firewall opens the L4 routes' ports (and SSH) alone, an install ends `<name> <version> is
running` with no URL, and `vm create` shows `served: no front, its L4 routes alone`. The flags
only a front takes (`--tls`, `--domains`, `--cert`, `--key`, `--ca`, `--client-ca`, `--http-port`,
`--https-port`, `--ports`, `--address` of the installer; `--tls`, `--domains`, `--http-port`,
`--https-port` of `vm create`) are hidden from the help and refused when given:
`<name> has no front: --tls set how a front serves, and its L4 routes are its only way in`, as is
a TLS mode or a front port in the VM's settings. An upgrade between a release with a front and one without is
refused (`… has no front, and this install serves through one: a release without a front needs a
new install`, and the reverse). On Kubernetes the chart is given no route; `stowage.l4` as
always. Its releases carry no front image: `ship` builds none, and an install pulls, records
(`STOWAGE_FRONT_IMAGE`) and preloads none.

**A front for L4 routes alone**: a front whose only work is terminating the TLS of `l4` routes
(`l4.routes[].tls`, with `front.tls_modes` and, optionally, `front.publish_ca`) leaves
`front.routes` and `front.portal` out. Lint refuses an empty `front.routes` only when no L4 route
has `tls` (`at least one route is required (or an l4 route with tls, the front terminating its
TLS)`); a `portal` may be left out only by such a front, without routes: one with routes, or a
`portal` given, must name a route (`… names no route: the installer ends by printing the portal
URL (a front without routes, serving l4 routes with tls alone, leaves it out)`). The
install asks the TLS mode, the L4 routes' domains (`--domains <l4 route>=<domain>`) and the front's
ports as for any front; each L4 route's domain is a site of the front's that answers 404 over
HTTPS, so its certificate is obtained, renewed and published (`publish_ca`) as a route's, and the
install ends `<name> <version> is running` with no URL, after its `L4 route <name>: …` lines.

**A project without a database** ([examples/stateless](../examples/stateless/stowage.yaml)) leaves
`database` out. `health` and the rest stay as they are; what only a database needs is
then refused where it is declared: a `pg-age-rclone` or `command` `backup` (`a <provider> backup
backs a database up, and the project declares none (volumes-age-rclone backs up the volumes of a
project without one)`) and a non-empty `data.reset` (`reset-db resets a database, and the project
declares none`); `data.volumes` alone stays the project's own, and a `volumes-age-rclone` backup
archives the volumes it lists (with a `kairos` shape, `data.volumes` and no `backup` is a warning:
`the VM keeps its data volumes locally and no backup is declared (volumes-age-rclone archives
them)`). A release whose `pg-age-rclone` backup has no database to dump — lint refuses it, so only
a release built past lint — has its backups and `restore` refused (409, `<name> <version> has no
database: its pg-age-rclone backup has nothing to dump`). Its installs skip the database
steps: an upgrade dumps nothing and records no schema version, a rollback (and the VM's fallback
at a failed health gate) goes back unchecked by any schema, and `reset-db` (Docker, the VM, `k8s
reset-db`) refuses, before anything changes, with `<name> <version> has no
database: reset-db has nothing to reset`; `restore` restores the volumes of a `volumes-age-rclone`
backup. On Kubernetes
`postgres_modes` is left out; the chart is given no database value either way.

| Key | What it takes |
|---|---|
| `apiVersion` | `stowage/v1` (another value: upgrade Stowage) |
| `name` | 2–40 lowercase letters, digits or `-`, starting with a letter; it prefixes every repository |
| `short_name` | optional, the same form as `name` (absent is `name`): the installer is `<short_name>-stow` — the binary that installs and runs the infrastructure's lifecycle. An install keeps it under that name and records it in its `.env` (`STOWAGE_SHORT_NAME`, not a value compose or a hook reads), so `short_name` is fixed for a project's life: `ship` refuses a release whose `short_name` differs from one its channels already hold, and an install refuses one before anything changes (a re-run, `upgrade`, `rollback`, the VM's boot) |
| `stowage.requires` | the Stowage versions the project accepts (see `stowage.requires` under the contracts): every command refuses a `stowage` outside it, lint errors on a range that does not parse and on a `stowage.lock` pin outside it, and warns when it is missing |
| `version.source` | `changelog` (default; `file`, default `CHANGELOG.md`, the first released heading), `file` (`file`, default `VERSION`, the first non-empty line), `git-tag` (`match`, a `git describe --match` pattern; `strip`, a prefix removed), `command` |
| `version.scheme` | `calver` (default; `format`, default `YYYY.M.MICRO`, tokens `YYYY YY 0Y MM M 0M WW 0W DD D 0D MAJOR MINOR MICRO` joined by `.`; `month_guard: utc\|local`, which needs a year and a month in the format: `lint` warns of a version out of its month, `ship` and `hook post-commit` refuse it), `semver` (no config), `regex` (`pattern`, anchored, with named groups; `order`, a list of `group:int` or `group:str` compared in turn), `command` |
| `changelog` | `keepachangelog` (default; `file`, default `CHANGELOG.md`; `## [x]` or `## x` headings, `Unreleased` skipped), `dir-per-version` (`dir`, required; `pattern`, default `{v}.md`, holding `{v}` once and no `/`), `command`. The current version must have a section |
| `channels.<name>` | `tag` (template holding `{v}` once), `mutable`, `latest`. Names are lowercase letters, digits, `.`, `_`, `-`. At most one channel sets `latest` (none, or a mutable one, is a warning) |
| `registry.prefix` | `<host>[:port][/path]`, the host a name or a bracketed IPv6 address (`[fd00::5]:5000/notes`): no scheme, tag or trailing slash |
| `registry.delete` | how the publisher deletes a manifest by digest (an older disk set, a pruned release's): `oci` (the default, the distribution API) or `github` (GitHub's packages API: `api`, default `https://api.github.com`; `token_env`, default `registry.push`'s, a token with `delete:packages`) |
| `registry.pull`, `registry.push` | `token` (`user`, `token_env`), `docker-config` (`config`, a Docker config directory; empty: the default Docker login), `none` (pull only). `registry.pull` is baked into every installer: it may not use `registry.push`'s `token_env` or Docker config. With `none`, `ship` refuses a repository the release writes that an anonymous read is refused (see `ship`) |
| `signing` | `cosign-key` (`key`, `public_keys`), or absent / `none` |
| `audit` | optional, a project that signs: the gate `ship` and `promote` pass before a channel points at a release (see "The audit gate" ([publisher](publisher.md)) under `audit`): `fail_on` (`negligible`, `low`, `medium`, `high`, `critical`; required), `fixable_only` (default `true`), `allow` (a file of the project's: `{id, artifact, package, path, reason, expires}` entries, `package` and `path` optional, each expiring at most a year ahead). The publisher's alone: it changes no release's inputs |
| `images.<key>` | built (`context`, `dockerfile`, `target`, `args`, `add_hosts`: `{<host name>: [<IP>, …]}`, the names the build's steps resolve to fixed addresses, each to every address of its list (a client's failover across them) — BuildKit's `/etc/hosts` is read-only to a step — each passed as `--add-host`; `network`: `default` (BuildKit's own), `host` or `none`, the steps' network, passed as `--network` (`host` with `--allow network.host`, its entitlement, which the builder must grant); `contexts`: `{<name>: <directory>}`, named build contexts, each a directory of the project passed as `--build-context <name>=<its absolute path>` in name order — a source a stage reads (`COPY --from=<name>`, or the stage of that name it replaces) that the main context does not hold, such as a submodule the main context's `.dockerignore` keeps out; no install reads it), which a hook ship takes from the working tree at the commit (see the publisher's hook); `required: true` refuses a ship while it is absent (`images.<key>.untracked: <path> is required and absent: …`), and by default one absent is built without; a promotion builds nothing and checks none) or `ref` (exclusive with the build keys, `contexts` among them). A host name that is not lowercase, an empty list, an address that is not an IP (or carries a zone), the same address twice for one name and another network are errors. An image no service or hook uses is a warning; a `# syntax=` frontend or a `FROM $ARG` cannot be checked (warning) |
| `stack.compose` | the compose file (its contract: "The contracts a project must honour"): `extends` within the file, `profiles:` only those an input's `profile` names, a `ports:` entry past this host an error with a `kairos` shape and a warning on `docker` |
| `tune.profile` | optional: the tuning profile of the hosts the `docker` and `kairos` shapes run on (see "Network tuning" ([tuning](tuning.md)) under the installer): `default` (the same as no `tune`: Docker's path as fast as the host's network) or `network` (a host serving a heavy network load); the operator may choose another (`--tune-profile`).
